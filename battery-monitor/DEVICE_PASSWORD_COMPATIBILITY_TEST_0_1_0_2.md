# Battery Monitor 0.1.0.2 — Device Password Compatibility Test

This is a focused addendum to `HARDWARE_TEST_PLAN_0_1_0_2.md` for the legacy setup-code compatibility boundary discovered during pre-hardware review.

## Purpose

Battery Monitor now supports arbitrary Device Passwords, but Windows, Android, and the embedded WebUI intentionally preserve compatibility with the historical printed setup-code shape:

`XXXX-XXXX-XXXX-XXXX`

Only an exact match to the historical restricted alphabet is canonicalized to the original 16-character value. Arbitrary custom passwords must remain byte-for-byte unchanged.

The historical alphabet is:

- digits `0-9`;
- letters `A-H`, `J-K`, `M-N`, `P-T`, `V-Z`;
- case-insensitive;
- exactly four groups of four separated by hyphens.

The letters `I`, `L`, `O`, and `U` are outside that exact compatibility pattern.

## Automated CI vectors

The Windows `--protocol-self-test` must pass these vectors:

- `ABCD-EFGH-JKMN-PQRS` -> `ABCDEFGHJKMNPQRS`;
- `abcd-efgh-jkmn-pqrs` -> `ABCDEFGHJKMNPQRS`;
- `ABCO-EFGH-JKMN-PQRS` remains unchanged because `O` is outside the legacy alphabet;
- `custom-password` remains unchanged;
- formatted and canonical legacy values derive the same protected-setup WPA2 key;
- formatted and canonical legacy values derive the same LAN management key.

## Hardware test A — formatted legacy-shaped Device Password

Use a disposable/test Device Password, not a production credential.

1. Start from a unit on the candidate `0.1.0.2` build with trusted USB available.
2. Set Device Password to `ABCD-EFGH-JKMN-PQRS` through the supported trusted-USB/admin path.
3. Verify USB `VERIFYPROVCRED` accepts the same formatted value.
4. If no home Wi-Fi is saved, confirm the protected setup AP starts immediately.
5. Use Windows secure provisioning with the formatted value and confirm WPA2 association succeeds.
6. Complete Espressif Security-2 provisioning and confirm the SRP proof succeeds.
7. After normal Wi-Fi comes up, confirm Windows LAN management unlock succeeds using the formatted value.
8. Repeat secure provisioning with the Android setup APK using the same formatted value.
9. Confirm Android can associate to the protected AP and complete Security-2 provisioning.
10. Enter `ABCDEFGHJKMNPQRS` without hyphens and confirm it is equivalent for authentication/provisioning.

**Pass:** firmware, Windows, Android, and embedded management semantics agree on the same canonical 16-character credential.

## Hardware test B — lowercase legacy-shaped value

1. Set Device Password to `abcd-efgh-jkmn-pqrs`.
2. Confirm Windows and Android accept that entered form.
3. Confirm the uppercase/hyphenless canonical value `ABCDEFGHJKMNPQRS` is equivalent.

**Pass:** legacy compatibility is case-insensitive exactly as the clients specify.

## Hardware test C — near-match must stay literal

Use:

`ABCO-EFGH-JKMN-PQRS`

This contains `O`, which intentionally excludes it from the legacy compatibility pattern.

1. Set that exact string as a custom Device Password.
2. Verify USB accepts that exact string.
3. Verify Windows secure provisioning succeeds with that exact string.
4. Verify Android secure provisioning succeeds with that exact string.
5. Verify LAN management succeeds with that exact string.
6. Verify `ABC0-EFGH-JKMN-PQRS` is **not** accepted as an equivalent password.

**Pass:** the firmware does not over-normalize custom passwords that merely resemble the old format.

## Hardware test D — arbitrary custom password

Choose an ordinary custom test value containing characters outside the historical pattern, for example:

`custom-password_42!`

1. Set it through the supported path.
2. Verify Windows provisioning and management.
3. Verify Android provisioning.
4. Verify reboot persistence.
5. Verify changing chemistry/settings does not affect the credential.

**Pass:** arbitrary custom passwords remain literal and interoperable.

## Migration note

Legacy split credentials generated by the original setup-code system remain supported: the stored legacy check hash is based on the 16-character canonical value, and current clients convert the printed hyphenated form to that value.

A short-lived pre-fix v2 build could theoretically have stored a newly chosen legacy-shaped password literally. Such a unit cannot be automatically converted without the plaintext password because the stored SRP verifier/hash are one-way values. If encountered, repair the Device Password through the trusted physical USB credential path before treating the unit as a validated hardware-test device.

Do not weaken password verification or add a plaintext credential store to automate that edge-case migration.
